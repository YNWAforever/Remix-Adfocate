## Strengths worth preserving (evidence)

- **Staff API authorization** denies by default through a route-capability table. The workspace and resource of every id is checked before the handler runs (`server/routes/admin.ts:67-111`, `server/lib/staffCapabilities.ts:58-101`).
- **Active-mission and publication-proof review** use `expectedState`/`expectedRevision`, idempotency keys, required reasons, row locks and append-only workflow events (`server/routes/adminActiveMissions.ts:805-956`). Notification failures don't roll back decisions.
- **Application decisions** are idempotent and first-writer-wins (`20261025120934_application_decisions.sql`).
- **Redemption intents** (`redeem_gift_with_request`) are idempotent under an advisory lock (`20261025194402_*`). `approve_submission` runs points, cash, budget and XP in one transaction under `FOR UPDATE`.
- **The creator API** never trusts a request-supplied creator id. Service-role paths are keyed to the JWT `uid` (`server/lib/activeMission/repo.ts:270-277`).
- **Proof URL fetching** has meaningful SSRF hardening: https only, public-IP check, redirect re-validation, size and time caps.
- **The test suite is large:** 2,402 unit and component tests. 78 migrations apply cleanly from scratch.
