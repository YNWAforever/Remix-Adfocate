## A-R.1 — Read-only capture of the source

- [ ] First prove `current_database() = 'postgres'`, `current_user = session_user = 'postgres'` after pooler routing, PostgreSQL 17 primary, correct project/endpoint, and compatible locale, extension versions, role/bootstrap and archive prerequisites. Compare the source's catalog against the proposed local image's available extensions before continuing. Require complete schema usage and table read access; stop on a read-only mismatch, foreign tables, nonstandard tablespaces, subscriptions or unavailable required extensions/catalogs. Source SQL is limited to reviewed catalog/data reads and session-local transaction settings. No source test write.
- [ ] Keep a source **keeper** session open in `REPEATABLE READ READ ONLY`, with `row_security=off` so a permission gap errors rather than silently hiding rows. Export a snapshot. Record the adjacent UTC capture time, current schema/permission baseline, and source-side counts and fingerprints from that snapshot. Keep the snapshot ID private. Start the native dump on the same source database with that exact ID, then end the keeper with `ROLLBACK` after both inventory and dump complete. PostgreSQL requires the exporting transaction to remain open for the import; see [snapshot synchronization](https://www.postgresql.org/docs/current/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION) and [pg_dump snapshot options](https://www.postgresql.org/docs/17/app-pgdump.html).

  Review reference for the exact transaction and tool flags. These fragments run only inside the approved capture worker, with the pinned connection and credential flow above; they are not commands to paste into a general terminal:

  ```sql
  BEGIN ISOLATION LEVEL REPEATABLE READ, READ ONLY;
  SET LOCAL lock_timeout = '2s';
  SET LOCAL statement_timeout = '60s';
  SET LOCAL row_security = off;
  SET LOCAL timezone = 'UTC';
  SET LOCAL datestyle = 'ISO, YMD';
  SET LOCAL intervalstyle = 'postgres';
  SET LOCAL extra_float_digits = 3;
  SET LOCAL bytea_output = 'hex';
  SELECT current_database(), current_user, session_user,
         current_setting('transaction_read_only'), current_setting('row_security'),
         current_setting('server_version_num'), pg_is_in_recovery(),
         transaction_timestamp() AS freshness_anchor_utc,
         clock_timestamp() AS exported_at_utc, pg_export_snapshot() AS snapshot_id;
  -- Execute the reviewed read-only source inventory in this same transaction.
  -- Keep the session open until the snapshot consumer and inventory finish.
  ```

  ```sh
  pg_dump --no-password --format=custom --create --snapshot="$snapshot_id" \
    --lock-wait-timeout=5s --file=/archive/database.dump.part
  pg_dumpall --no-password --database=postgres --roles-only --no-role-passwords \
    --file=/archive/roles.sql.part
  ```

- [ ] Capture the role file separately, after the keeper ends, with no role passwords. Compare role attributes, memberships, grantors and options from the keeper snapshot with both sides of the role export; any drift blocks the run. Compare a final short catalog read with the snapshot's schema/ACL inventory to detect concurrent schema or permission drift. Ordinary business activity after the snapshot is allowed and is not compared to a later row count. Sequences are checked against archive-captured state, since their counters can advance outside the row snapshot.
- [ ] Require successful completion, expected archive identity and full scope. Keep the native custom archive, roles SQL, native table of contents (`toc.list`) and `manifest.json` together under `archive/`. Manifest: source ref, candidate/evidence, timestamps, UTC snapshot provenance, versions, sizes, SHA-256 for the three files, role comparison result, bytes transferred, and expected exclusions. Close the source sessions, confirm no capture worker can reconnect, then rename partial files to their final names and seal them. A failed/partial capture is never a restore point.

Reject corruption, warnings or missing critical objects. Stop if the archive contains subscriptions, required foreign data outside the dump, unsupported tablespaces or incompatible extensions. The existing two-pass event-trigger path also stops on `MATERIALIZED VIEW DATA`; resolve that ordering explicitly before a new approved attempt. Do not omit an object to make the restore pass.
- [ ] Create the one run-labeled container from the pinned local image: `--pull=never --network=none --read-only --cap-drop=ALL --security-opt=no-new-privileges --log-driver=none`, as `postgres`, with private bounded tmpfs for `/tmp` and any approved image data-volume destinations. Require zero port bindings, no writable host data mount, no Docker socket, no inherited source credentials, and no unexpected volumes. Mount the archive and reviewed checks read-only. Verify those conditions against the created container ID before attaching the run. Docker documents [the no-network driver](https://docs.docker.com/engine/network/drivers/none/).
- [ ] Use the native restore script's reviewed order: fresh `initdb` with the source-matched bootstrap role and supported locale, local socket only, no shared preload workers, and only the reviewed Supautils session support needed for ownership. Restore roles with `psql -X --no-password -v ON_ERROR_STOP=1`; remove only the single redundant bootstrap-role `CREATE` from a scratch copy after exact-match validation. Use the control database to restore the archive's `postgres` **inside that container** with `pg_restore --exit-on-error --clean --if-exists --create`. Follow with the event-trigger pass under the original owner, using the verified TOC partition. Every TOC item must be accounted for exactly once. Do not use `--no-owner`, `--no-acl`, source URLs, or skip errors.
- [ ] Confirm there is no PostgREST, Auth, Storage, scheduler, application, provider worker, or public listener attached. Do not start cron or call webhook/network routines from the restored data. Capture actual duration, zero restore errors, and completion status; recheck the unchanged input hashes.

**Recovery boundary.** A database archive can restore Storage metadata and proof references, but does not include Storage object bytes. It also does not recreate hosted Auth behavior, platform settings, source encryption root keys, role passwords, external integrations or PITR/WAL. See [Supabase database backup coverage](https://supabase.com/docs/guides/platform/backups). Keep the clone quarantined permanently. Record Storage file bytes as `NOT_RUN`; if the later change or its rollback depends on any such file, key or platform setting, keep that change on hold until the owner approves and verifies a separate recovery plan for it.

## A-R.4 — Close out, dispose and report

1. End the keeper/dump/role-export processes on success, failure or cancellation. Confirm the dedicated source and restore processes are gone and release the credential. A failed source read or restore never triggers a source repair, a hosted restore or a retry.
2. Produce a local cleanup list with the exact container IDs and run label, scratch paths, expected retained archive and expiry. Verify the local engine, ownership label and each resolved absolute path; reject symlinks, reparse points and anything outside the exact run directory. Stop and remove only those containers and their owned tmpfs/anonymous volumes. Verify the IDs no longer exist and remove only this run's scratch and partial files. No Docker prune, old backup deletion, remote row cleanup or source database deletion.
3. Retain at most one verified archive under the approved encrypted private root for **48 hours** from capture, unless a separately approved change hold requires it longer. On failure retain only the minimum encrypted diagnostic material for up to **24 hours**, subject to owner policy; no failed archive counts as recovery. The operator records disposal and rechecks that retained files have no extra copies, synced folders or public paths. At expiry, verify the exact path and delete the sealed copy with owner-approved media handling. Keep the redacted receipt per the approved review policy.
4. The independent reviewer signs one sanitized `scope-a-r-receipt.json`: candidate/evidence IDs, source ref, local target alias, capture/completion/expiry times, manifest hash, snapshot/role/catalog comparisons, cases `PASS/FAIL/NOT_RUN`, measured restore time, estimated/observed egress, actual cost, disposal readback, and limitations. Keep credentials, snapshot IDs, record identifiers, raw data and logs in the restricted local run only. Report `DB_RESTORE_VERIFIED` only if required comparisons pass and cleanup is confirmed. Otherwise record `BLOCKED` with the failed or missing check and leave B6 open.
5. A later A.4 review requires a signed receipt, the still-readable recovery copy **at most 24 hours old at execution**, and a new read-only schema/ACL drift and impact check against that same source. If older, expired, mismatched or unavailable, obtain a new approved capture. No rollout or broader P5 gate opens from A-R alone.
