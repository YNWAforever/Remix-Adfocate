# D1 stop, retention and restore

This is the prepared procedure. No remote pilot, scheduled job or provider grant currently exists; no remote drill has passed.

1. Freeze the approved target receipt and reject new admission. The dedicated pilot entry already starts closed. Recheck both new and in-flight requests. Do not enable the ordinary application as a fallback.
2. Keep real OAuth, token exchange, content fetches, Picker and external AI disabled. Stop the separately approved maintenance trigger if it exists; do not alter existing product cron jobs.
3. On an admitted isolated target, retain local owner revoke/purge and minimal receipt inspection through the restricted management path. Report remote revocation as pending/manual action until separately proved. No full environment deletion as a shortcut.
4. Preserve sanitized run ID, artifact/source/schema identities, operation counts and exact fixture IDs. Do not preserve token/code/query/body dumps. Escalate any wrong-target write; do not attempt unauthorized cleanup of the product.
5. Before restoring a backup, quarantine the entire restore target at network, Auth, API and application access layers. A row flag is insufficient. Restore the independently kept tombstone log and required encryption key versions, replay all deletions, then test ordinary JWT/direct API and Studio readers while still quarantined.
6. Release quarantine only when the exact restored backup horizon and complete tombstone coverage are documented and ordinary identities cannot recover deleted private content. Missing keys/tombstones/horizon or inability to isolate is **BLOCKED**.

Retention targets are 30 days for unreferenced snapshots, 24 hours for revoked unreferenced snapshots and 90 days for minimal events. Process at most 100 per batch, lease before destructive retention, dry-run first, and alert on delays beyond the next hourly window. A local algorithm passing tests does not establish a running scheduler or those deletion guarantees.

Only recorded disposable pilot IDs may be cleaned within seven days of pilot end. Owner, independent key/tombstone storage, backup retention and hosted scheduler are unresolved in [target.md](target.md). No actual restore or cleanup should run from this document alone.
