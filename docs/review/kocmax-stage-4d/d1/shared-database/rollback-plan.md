## SQL 尚未提交

更新包只准使用一條專用連線及單一交易。只移除來源檔的最外層 `BEGIN/COMMIT` 來組裝原子交易，函式內容不改寫；每份原檔和導出版本分別有 hash。不可逐檔用不同連線貼上並提交。

鎖等候上限 2 秒，單句上限 30 秒；不自動重試，不終止其他工作階段。錯誤或任何驗收失敗，在同一連線執行 `40-abort-open-transaction.sql`。交易中斷則由 PostgreSQL 放棄未提交內容；應核實連線／交易已結束，不能只根據網頁超時推斷已回退。

更新交易未提交前的 DDL、函式替換、權限、觸發器、檔案庫設定及交易內資料變更均隨 `ROLLBACK` 撤回。此承諾不涵蓋外部網絡動作或交易外檔案操作，因此本包沒有加入這些操作。

## 測試資料

`30-fixture-transaction.sql` 固定以 `ROLLBACK` 結束，只使用清單中的新 ID、四個明確綁定的專用 Auth 身份，以及伺服器返回的交易內 ID。碰撞即停止，沒有 upsert 或重新使用現有創作者的路徑。

先產生測試 workspace、角色、草稿任務、未驗證來源與私人 Brief，再以 SQL claim 替身檢查個人／同工作區／跨工作區權限和匿名權限；這不是實際 JWT 驗收。Brief 不派積分、現金、XP 或徽章。此包沒有實際積分結算、發佈證明或兌換步驟；完整任務／入帳演練另列驗收項，不能由此包冒稱通過。

完成或失敗後一律回滾，再以 `41-after-rollback.sql` 檢查精確根記錄及身份 ID 無殘留；缺少身份參數使該驗證無效。不要刪除 Auth 帳號：它們在本包以外建立，是否可刪除要有獨立擁有權與清理批准。

此模式的資料不會跨連線可見，所以不能供瀏覽器操作。若要持續的手機／桌面試點，另行審閱固定寫入清單、帳號、期限及清理程序；不可把本檔最後一行改成 `COMMIT`。
