The verifier does not modify the manifest or any archive file and requires precisely `manifest.json`, `database.dump`, `roles.sql`, and `toc.list` in that directory.

Before Docker, it checks the exact private root, absence of reparse points, separation from repository/visualization roots, current-user/SYSTEM-only ACLs, current branch, manifest target/image/status, exact `helperVersion: 3-native-readonly-20261101`, successful pinned-CA TLS metadata, no failure/active container, and exactly three unique artifact names with matching sizes/hashes. Database metadata must report transaction_read_only on and row_security off; default_read_only must be on/off but need not be on. A v2 manifest is not current v3 evidence. Capture script SHA-256 is reported for parent provenance review; hashes are consistency checks, not signatures or proof of source completeness.

The existing official PostgreSQL 17 digest is fixed. Docker uses the local Linux-engine named pipe, `--pull=never`, `--network=none`, a read-only root filesystem, disabled logging, no published ports/socket mounts/credential forwarding, and only the selected directory as a read-only bind mount. It invokes `pg_restore --no-password --format=custom --file=/dev/null /backup/database.dump` without a database argument or filters. Native stdout/stderr is never printed or saved; any unexpected output/error causes failure. Only the verifier's own UUID container may be removed.

PostgreSQL documents that omitting the database argument produces a SQL script instead of executing it; sending that complete output to `/dev/null` exercises archive reading/decompression without writing SQL to a file or database. This is stronger than a table-of-contents listing, but it is **not a restore rehearsal**. [PostgreSQL 17 pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)
