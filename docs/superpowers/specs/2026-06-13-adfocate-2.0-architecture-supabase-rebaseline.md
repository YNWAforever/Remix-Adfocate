# Adfocate 2.0 — Architecture Re-baseline & Slice Roadmap (Supabase/Vercel)

- **Date:** 2026-06-13
- **Status:** North-star — reconciles the full product spec with the deployed stack
- **Reconciles:** the provided full spec `adfocate-2-spec.md` ("Adfocate 2.0 — Full Product Specification", v2.0.0, Greenfield Rewrite) onto the **already-deployed** Slice 1 stack.
- **Decision (brainstorming):** **Keep Supabase + Vercel; re-baseline the spec's infra** to Supabase-native primitives. Do not migrate to the spec's Zeabur/Prisma/Redis stack.

## 1. Why this doc exists

The full spec proposes a backend stack we already chose differently and shipped. Most starkly, the spec **rejects RLS in favour of schema-per-tenant**, but Slice 1 is live **on RLS**. This doc is the authoritative mapping from the spec's vision to our deployed reality, plus the slice roadmap. Where the full spec and this doc disagree on **infrastructure**, **this doc wins**; the full spec remains the source of truth for **product scope, domain models, and features**.

## 2. Divergences resolved

| Dimension | Full spec | Deployed (Slice 1) → **adopted** |
|---|---|---|
| Multi-tenancy | schema-per-tenant | **Row-level RLS + `workspace_id`** |
| Data access | Prisma | supabase-js + SQL migrations |
| DB / infra | Zeabur Postgres + Redis + BullMQ | **Supabase** (Postgres + Auth + Realtime), serverless |
| API host | Hono on Zeabur | **Hono on Vercel** |
| Frontend host | Cloudflare Pages | **Vercel** (React 19 + Vite + TanStack) |
| Base codebase (§12.4) | evolve `refreshing-adfocate` in place | **fresh `adfocate-2`** repo (port design across) |
| Theme example (§8.3) | pastel `#FFB5C2` | **neon Acid Y2K** |

The framework layer (React/Vite/TanStack/Hono) already matched.

## 3. Re-baseline mapping (spec concept → Supabase-native)

| Spec concept | Spec's choice | Re-baselined |
|---|---|---|
| Multi-tenancy | schema-per-tenant | **RLS** via `private.current_workspace_id()` (live) |
| ORM | Prisma | supabase-js + `supabase/migrations/*.sql` |
| Auth | custom JWT + OAuth | **Supabase Auth** — OAuth (Google/Apple/LINE) + Email/Phone OTP |
| Realtime / notifications | Hono WebSocket | **Supabase Realtime** (Postgres Changes) |
| Jobs & queues | BullMQ + Redis (Zeabur workers) | **`pg_cron`** (point-expiry, xp-recalc, finance-score, mission-deadline, SLA-enforcer) + **Supabase Queues (pgmq)**; triggered/served by **Edge Functions** + **Vercel Cron** |
| AI agent workers | Zeabur worker processes | **Supabase Edge Functions** invoked by cron/queue; **OpenRouter** unchanged (Claude primary, GPT fallback) |
| Cache | Redis | Postgres + HTTP cache; add Upstash Redis only if a measured hotspot needs it |
| Media | Cloudflare R2 | **Supabase Storage** (or keep R2 — both S3-compatible) |
| Payments | Stripe | **Stripe** (unchanged) — webhook via a Vercel route |
| Observability | Axiom + Sentry | **Sentry** + Supabase logs (Axiom optional) |

The CPM 30-day view-polling is the one piece that genuinely needs a scheduled job → `pg_cron` + an Edge Function when Slice 9 lands.
