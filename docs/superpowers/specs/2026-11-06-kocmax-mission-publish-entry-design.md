# 品牌核准作品：任務頁發佈入口（mock）

狀態：用戶已批准；實作計畫待審閱。日期：2026-11-06。

## 意圖與範圍

讓創作者從品牌任務頁，把已核准作品交到 Instagram：任務核准 → 核對帳號、圖片、文案與披露 → 創作者確認 → 發佈結果 → 原任務證明核對。

這是既有 mock 發佈流程的有限入口整合，非新增完整發佈平台。沿用現有 TypeScript／React、任務工作區、發佈政策、預覽及結果元件；此技術選擇由實作者提出。品牌核准不代表代替創作者授權發佈。

## 已選方案與取捨

- **任務頁入口（用戶已選）**：在具體交付項目的核准版本旁操作，任務與版本明確；需前往該任務。
- **對話入口（本期不採用）**：對話中要求發佈較方便，但需處理多任務及版本選擇，容易增加確認負擔。

用戶已確認品牌核准後仍由創作者最後核對並按一次確認發佈。已展示可點擊視覺概念，檔案位於 `.superpowers/brainstorm/2005-1793897880/content/mission-publish-concept.html`。

## 互動與邊界

1. 在原任務交付項目呈現「發佈到 Instagram」入口。適用既有 Active mission 的 `approved_to_publish` 核准作品；本期只有單張靜態圖片貼文。舊版任務及其他格式沿用原流程。
2. 以該交付項目的核准版本取圖片與文案，不能直接把已保存 Brief 當成核准作品。呈現目標帳號、核准版本、最終圖片、完整文案、必要披露及權限狀態。
3. 創作者核對後才能按「確認發佈」。更改帳號、授權、素材、文案、任務指示或核准版本，使舊確認失效。修改作品回原草稿／審核入口，不在確認畫面靜默改稿。
4. 發佈只包含已核准的最終圖文與必要披露，不夾帶私人來源文件、摘要或討論。當前來源權利及授權仍須有效；既有私人來源限制不被任務核准繞過。
5. 發佈中停用重複確認。同一要求結果不明時只查詢原要求，不能盲目建立第二次發佈；保留既有冪等及版本政策。
6. 成功回執引導回原任務核對證明，再由原流程確認提交。mock 回執清楚標示示例，不當作真實貼文、有效證明、任務完成或積分依據。
7. 必要合作標籤／品牌標記不支援或未核實時阻止直接發佈，提供原手動發佈及提交證明入口。文案標示合作不能自動代替必要的平台標籤。
8. 未連接、已撤銷、授權不足或帳號不符時顯示具體阻斷原因。Username／bio 驗證／RapidAPI 資料不得當成發佈權限。真實官方授權與協定驗收仍屬後續獨立階段；本期只模擬其狀態。

## 手機與桌面

沿用遊戲化任務卡、私人／核准徽章及清楚的三步進度。手機單欄、主要操作至少44px；桌面主欄預覽與側欄任務提示。核准後不自動發佈；不製造倒數壓力或發佈即得獎的誤導。沿用既有導覽、來源與任務資訊。

## 驗收

- 在390×844及1440×1000完成 mock 任務入口 → 核准預覽 → 明確確認 → 回執 → 任務證明核對入口。
- 測試未核准／核准失效、帳號變更、授權撤銷、私人來源不可分享、必要標籤不支援、重複點擊、結果待確認及登入失效。
- 取消預覽不改任務；返回／重新載入不偷偷重發，不把遺失的 mock 狀態宣稱為已發佈。
- 示例與入口的開發演示資料不進入正式 bundle；不呼叫真實發佈、證明提交或獎勵寫入。
- 保存成果、原任務／審批／手動證明路徑保持可用，執行相關回歸、TypeScript、lint及建置隔離檢查。

## 不包含與交接

不部署、不套用SQL、不建立真實Instagram／Drive連接、不提交真實貼文。沒有排程、Reels、Stories、輪播、多平台、自動發佈或新增獎勵規則。不 stage／commit；留在現有分支。

實作者需在 implementation plan 核對具體任務元件與既有 mock adapter 接點，重用現有確認／回執邏輯，避免另一套狀態機。概念中的支援標籤、帳號及回執僅為情境示意，不是實際能力的宣告。上一階段列明的焦點相容性 minor 保持可追蹤，不宣稱已修復。
